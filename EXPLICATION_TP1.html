Le but : sortir du notebook

Un notebook marche pour explorer, pas pour la production. Le TP1 pose le quartier general sur lequel tous les TP suivants se branchent : un environnement reproductible, un depot Git propre, un script executable.

Objectif A - Script

Passer du notebook a train.py, executable en une commande.

Objectif B - Environnement

Decrire les dependances dans environment.yml (Conda), pas dans un README.

Objectif C - Git / GitHub

Versionner le code, ignorer les binaires, publier sur GitHub.

Le code, fichier par fichier

Ouvre le projet dans VS Code : chaque script commence par le meme resume (ROLE / ENTREE / SORTIE / A RETENIR). Lis-les dans cet ordre, c'est l'ordre d'execution.

environment.yml   -> la liste des paquets (recette de l'environnement)
.gitignore        -> ce que Git ne doit JAMAIS suivre (env, data, modeles)
train.py          -> le script de production

1. train.py

Role : Premier script de production : charge Iris, entraine une foret aleatoire, sauvegarde le modele.

Entree : le jeu Iris de scikit-learn

Sortie : models/iris_model.pkl (ignore par Git grace au .gitignore)

A retenir : Un script s'execute de haut en bas en une commande (python train.py), contrairement a un notebook.

Resultat cle

git status apres python train.pymodels/iris_model.pkl existe sur le disque mais n'apparait PAS : les regles models/ et *.pkl l'excluent.

Ce qu'il faut retenir

  • Environnement = code : un fichier versionne (environment.yml puis requirements.txt) recree le meme environnement partout. Un README ne s'execute pas.
  • Un projet = un dossier = un environnement = un depot. On ne melange jamais les dependances de deux projets.
  • Le .gitignore se decide AVANT le premier commit. Un gros fichier commite reste pour toujours dans l'historique.
  • Script > notebook pour la prod : execution de haut en bas, sans etat cache, automatisable (CI, cron, Docker), revisable en diff.
  • Git versionne du texte. Donnees et modeles iront ailleurs (DVC au TP3, registre MLflow au TP2).

Pieges

Le CSV de 2 Go commite par erreurDepot enorme pour tous les clones, push refuse par GitHub (limite 100 Mo), impossible a enlever sans reecrire l'historique, diffs illisibles, risque de fuite de donnees sensibles.
Mauvais interpreteur dans VS CodeCtrl+Shift+P -> Python: Select Interpreter -> celui du projet. Sinon le code tourne avec un autre Python.
